# 授权政务网页采集盒子：方案总结

面向已经拿到采集许可的场景：在政务电脑上自动采集业务网页数据，做成可打壳交付的边缘盒子。  
本文汇总目标边界、技术路线、硬件选型和落地顺序，便于内部对齐。

---

## 1. 目标（已收窄）

要做的是：

- **授权范围内**的自动采集（许可写清操作人、目的、URL 范围、有效期）
- 对象是政务电脑里的 **网页界面**
- **DOM 优先**抽表格/字段；图片、扫描件、canvas 走 **OCR**
- 需要筛选时，用 RPA 点下拉、填查询，再抽结果
- 默认 **只读**：可以查询、翻页、抽取；不替人提交审批、不回写业务库

不要做的是：

- 复刻北大信研院 / 燕云那套「通用黑盒反射 OS」（运行时体系结构重建、内存分析）
- 未授权采集、键盘记录、注入、绕过登录
- 一上来做「一个适配器打天下」

燕云的核心是十年系统软件 + 专利；我们要的是 **授权非侵入采集运行时 + 数据目录/API 外壳**。Fable 5 / GPT-5.6 级别模型适合当实现引擎，不适合当系统软件实验室。

---

## 2. 三个词：DOM、RPA、OCR

| 名称 | 是什么 | 什么时候用 |
|---|---|---|
| **DOM** | 网页 HTML 结构（表格、输入框、选项节点） | 能选中文字、检查元素能看到标签时。快、准 |
| **RPA** | 模拟人点、选、填、等 | 要先筛选、翻页、点查询时。每一步都可以是 RPA |
| **OCR** | 对着截图/扫描件把字认出来 | 字在图上、结构里拿不到时。慢、可能认错 |

**下拉几级、每步都要点，不等于每步都要 OCR。**  
多数政务页是：RPA 去点 + DOM 去读选项。只有选项是图片、canvas、云桌面、ActiveX 时，才变成「截图 → OCR → 按坐标点」。

填写查询条件（事项名、状态、日期）是为了把数据调出来，仍算只读采集。  
提交审批、改状态、保存业务单是回写，要单独授权，第一版不做。

验证码、UK、短信：停下来等人，不破解。

## 3. 两条采集架构（按现场选一条）

### 路线 A：软件 RPA（优先）

电脑能装采集程序，或能把盒子挂到 **已登录的 Chrome**（CDP）。

```
工作人员登录业务系统
  → 采集器挂到该浏览器 / 本机打开页
  → 点下拉、填查询（RPA）
  → 抽表格（DOM）
  → 扫描件截图（OCR）
  → 本地 JSON + 审计日志
```

优点：稳、能对账、不必外接键鼠。  
仓库里的 `awcollector` 就是这条线的骨架。

### 路线 B：硬件 RPA（电脑不让装软件时）

```
政务电脑 HDMI ──► 盒子 HDMI IN / 采集卡（看见屏幕）
盒子串口 ──► CH9329 ──USB──► 政务电脑（伪装键鼠）
```

- **CH9329 不是所有 RPA 的标配**，只是「这台电脑什么都不能装」时的外接手
- 它只负责动手，不负责看见屏幕；没有抓屏就是瞎的
- 这时才会变成逐步「RPA + OCR」，又慢又脆，分辨率必须固定

能走路线 A 就不要上 CH9329。

## 4. 软件怎么落地

许可门禁（没有有效许可拒绝运行）→ 任务 YAML（点、等、抽）→ 审计（谁、何时、哪个 URL、是否 OCR）。

采集策略：

1. 能 DOM 的全部 DOM
2. 需要认字：现成中文 OCR（PP-OCR / RapidOCR），**一般不需要训练**
3. 转 RKNN 是格式转换，不是训练
4. 盖章挡字、手写、长期不准，再考虑微调

MVP 建议先打穿 **1 个已授权系统 + 1 张核心列表/详情页**，能量化准确率再复制下一页。

仓库用法（软件 RPA 演示）：

```bash
python -m pip install -e ".[dev]"
python -m pytest
awc run --permit configs/permit.example.json \
  --task configs/tasks/demo_gov_list.yaml \
  --mode html --ocr-text "许可编号 DEMO-2026-001"
```

真实内网把许可里的 URL 前缀改成办事系统地址，`--mode cdp` 挂到已登录浏览器。

## 5. 硬件结论

瓶颈是 **内存、浏览器稳定性、7×24、供电和壳**，不是 TOPS。网页采集不靠 Hailo。

### 5.1 芯片与整机

| 选项 | 结论 |
|---|---|
| 树莓派 5 + Hailo | 可当实验室玩具；政务量产不合适，Hailo 对网页采集过剩 |
| Jetson Orin 系列 | AI 学习套件，不对口，别买 |
| 正点原子 RK3588 全接口学习板 | 芯片对，板太大太密，难打壳 |
| 4GB + 仅安卓工控板 | 不买（Chrome 不够用，Playwright 不是安卓 App） |
| 香橙派 5 Plus 16GB | 能开发；若已买对规格的工控主板，不必再买 |
| **RK3588 16GB Linux 主板（如 DC-A588 16+128G）** | **样机优先** |

推荐规格：

- SoC：RK3588
- 内存：**16GB**（8GB 仅演示）
- 存储：eMMC 64G 以上，数据盘可再加 SSD
- 系统：必须能刷 **Ubuntu / Debian**（政务可加麒麟）；不要只能安卓
- 网口：双千兆更好（业务网 / 上报网）
- 供电：12V（或 9–36V），按 5A 预留
- 看门狗、来电自启、RTC
- HDMI IN：路线 B 或整屏备用时有用，正路仍是 DOM

**不要加 Hailo。** DC-A588 的 M.2 多半是 4G（USB），不是 Hailo 要的 PCIe；板载 6 TOPS NPU 做 OCR 够用。两套 NPU 工具链不值得。

### 5.2 工控机还是开发板、要不要壳

- 规格能锁死（Linux + 16GB），**直接买工控主板做样机**，避免香橙派上跑通再搬一次驱动
- 先劝开发板，是为了躲开「4GB 安卓广告机」这种错的工控件
- **量产壳自己定制没问题**。「带壳」是指开发时要能固定、能散热，不是必须用商家通用铁盒
- 买：核心板/主板 + 孔位图 + 接口坐标；先 3D 打印临时壳，再开模
- 裸板防：短路、网线扯松、RK3588 跑 Chrome 过热降频

打壳预留：双网口、12V DC、USB、HDMI（可选 IN）、散热铝板。M.2 留给 SSD 或 4G，不要给 Hailo。路线 B 再加：USB 出（CH9329→电脑）、HDMI 进。

### 5.3 已看过的商品怎么判

| 商品 | 判 |
|---|---|
| CTFLY rk3588-A 4G+64G 安卓 | 不买 |
| 香橙派 5 Plus（16GB 约 2800） | 可开发 |
| 开发板热销榜 Jetson / Orin | 不买 |
| 正点原子 ATK-DLRK3588 | 仅学习，不当产品主板 |
| 8GB RK3588 + 风扇亚克力 + 10.1 寸屏 | 方向对；升 16GB、去掉屏、确认 Linux |
| **DC-A588 16+128G**（Debian/Ubuntu/麒麟、双千兆、148×106mm） | **第一台样机优先这款**，不配屏 |

DC-A588 下单确认：默认 Linux 能 SSH；12V；看门狗/来电自启；CAD 孔位；散热高度。

---

## 6. 建议落地顺序

1. 书面许可 + 锁定 1 个系统、1 张列表页  
2. 看选项文字能不能选中 → 能则 DOM；不能则该层才 OCR  
3. 硬件：DC-A588 16G Linux 无屏，临时壳开发  
4. 软件：许可门禁、查询下拉、抽表、审计  
5. OCR 不够再调截图，不要先训练、不要先 Hailo  
6. 电脑完全不能装软件，再加 CH9329 + HDMI 抓屏  
7. 一页稳定后再复制 adapter，最后按孔位开量产壳  

---

## 7. 一句话

**授权只读采集政务网页：能进 DOM 就进 DOM，要用手点就 RPA，字在图上才 OCR；硬件用 RK3588 16GB Linux 主板自己打壳，不要 Jetson/Hailo/安卓广告机；电脑不让装软件时才上 CH9329。**
