# 口播库：用已授权的抖音视频建知识库

短视频里的知识，默认是一次性的：刷过就散。要建成知识库，不要去爬别人的作品，而是把**你已经有权使用的口播**拆成四层、带时间戳入库，然后再检索和追问。

本仓库是一套可在本地跑的工具：文案/字幕优先，视频文件可选。网页打开后会先写入三条方法示例，你可以直接搜「抖音视频怎么建立知识库」。

## 方法（比工具更重要）

一条抖音视频通常叠了四层信息，缺一层，知识库就会飘：

| 层 | 从哪来 | 为什么要留 |
|---|---|---|
| 元数据 | 标题、话题、账号、分享链接 | 用来引用和合集，不靠它当正文 |
| 口播 | 语音转写，或剪映/创作者文案 | 真正可检索的主体 |
| 画面字 | 字幕、大字报、步骤条 | 很多口播把要点写在画面上 |
| 笔记 | 你当时为什么存这条 | 把「别人的讲法」变成「你的用法」 |

落地时按这个顺序做：

1. **只收有权用的素材**：自己的作品、客户书面授权、团队培训。别人的视频即使用分享链接能打开，也不该进你的库。
2. **先拿到文案**：剪映导出 SRT，或把口播稿贴进来。有时间轴就保留时间轴。
3. **按句子切开**：每段带 `00:12` 这样的位置，追问时能回到原片。
4. **抽出卡片**：观点、步骤、金句、术语。卡片是知识库的目录，原句是出处。
5. **先检索、再追问**：检索找原句；追问只拼接已入库的片段，不编造。

## 自己的视频从哪来（官方路径）

- 抖音 App → 我 → 作品 → 保存到相册（仅自己的作品）
- 剪映 / 创作者侧导出字幕或口播稿
- 企业/服务商走[抖音开放平台](https://developer.open-douyin.com/)里需用户授权的视频能力

分享链接在本工具里**只解析编号作引用**，不会请求抖音去下载、去水印或跟跳短链。

不要用非官方「解析接口」、水印破解或批量抓取他人主页。那既违约，也建不出干净的知识库。

## 安装

```bash
python -m pip install -e ".[dev]"
```

需要抽音轨时，系统里要有 `ffmpeg`。语音转写是可选项：`pip install -e ".[asr]"` 后才会调用 faster-whisper。

## 命令行

```bash
dykb --data ./data init
dykb --data ./data seed
dykb --data ./data ingest --title "一周复盘四步法" --transcript fixtures/sample.txt
dykb --data ./data ingest ./my.mp4 --title "客户授权口播" --transcript ./my.srt --url "https://www.douyin.com/video/……"
dykb --data ./data search "知识卡片"
dykb --data ./data ask "抖音视频怎么建立知识库"
dykb --data ./data serve --host 127.0.0.1 --port 8000
```

`ingest` 可以只有文案、没有视频。很多创作者真正稳定的是剪映稿，而不是成片文件。

## 网页

```bash
dykb serve --port 8000
```

打开 `http://127.0.0.1:8000`：知识台、入库、检索、追问。首次启动会写入三条示例口播。

## 项目结构

```
src/dykb/     解析链接、切片、卡片、SQLite 检索、追问、CLI、网页
fixtures/     示例文案与 SRT（不是真实抖音成片）
tests/        解析、切片、入库、检索、网页
```

本地索引用 SQLite FTS5 + jieba，不依赖云端向量库。之后若要接自己的大模型，把 `/api/search` 命中的片段当作上下文即可。
